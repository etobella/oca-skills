# Odoo 16.0

Rules for writing an addon for 16.0: which API to use, and which one is
deprecated or replaced. The source is the framework changes listed in the
OCA migration guide to 16.0, with the Odoo change that introduced each one
(`odoo/odoo#...`). It is not a list of changes to the data model of each Odoo
module (see the `upgrade_analysis.txt` files of the OpenUpgrade project), and
the steps to migrate a module are not part of this file.

For constructs that are not listed here, follow
[Check the version before using an API](../guidelines/python.md#check-the-version-before-using-an-api).

## Search names

To expose the fields that a name search looks into, set the class variable
`_rec_names_search`; do not override `name_search` for it (odoo/odoo commit
`3155c3e42558`).

## Views and groups

- Do not set `groups_id` on a view. Put the group on the elements of the
  view instead: a view field can now carry a `groups` attribute, so there is
  no need to isolate it in a view of its own for fear of an access error
  (odoo/odoo#98551).
- A field protected by a group can take part in business logic or in the
  UI: the domain of another field, a copy, a default. `company_id` is the
  special case: Odoo always uses it internally in the domains of many2one
  fields that point to multi-company records. In these cases declare the
  field twice, once with the group and once invisible without it
  (odoo/odoo#95729).
- A one2many field outside a notebook does not take the full width of the
  form by default. Set `colspan="2"` to get that.

## Fields

- Set `unaccent=False` on a field where accented and unaccented words are the
  same for the search, to get better performance. `parent_path` is an example
  (odoo/odoo#76436).
- A field `index` accepts several types of index, depending on the purpose
  (see `odoo/fields.py`). `btree` is more expressive than `True`.

## ORM methods

- Get a view definition with `get_view`, not `fields_view_get`.
- Get the definition of the fields with `_fields` or `get_views()`, not
  `fields_get_keys()`.
- Get an external id with `get_external_id()`, not `get_xml_id()`.
- `flush()` and `recompute()` are deprecated. Use `flush_model()`,
  `flush_recordset()` or `env.flush_all()`, according to the granularity you
  need.
- `refresh()` and `invalidate_cache()` are deprecated. Use
  `invalidate_model()`, `invalidate_recordset()` or `env.invalidate_all()`,
  according to the granularity you need.

## Assets and templates

- Declare an XML assets template in the regular bundle of its scope
  (`web.assets_backend`, `web.assets_frontend`...), not in the fake bundle
  `web.assets_qweb` (odoo/odoo#95500).
- Reports, QWeb templates and website elements use Bootstrap 5, not
  Bootstrap 4.

## Tests

- Use `BaseCommon` as the base class of the tests: it reduces the overhead of
  tracking and speeds up the test suite.
- Create the records shared by the tests of a class in `setUpClass`, not in
  `setUp`: it runs once, so it is much faster.
