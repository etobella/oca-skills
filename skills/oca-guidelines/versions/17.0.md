# Odoo 17.0

Rules for writing an addon for 17.0: which API to use, and which one is
removed or replaced. The source is the framework changes listed in the OCA
migration guide to 17.0, with the Odoo change that introduced each one
(`odoo/odoo#...`). It is not a list of changes to the data model of each Odoo
module (see the `upgrade_analysis.txt` files of the OpenUpgrade project), and
the steps to migrate a module are not part of this file.

For constructs that are not listed here, follow
[Check the version before using an API](../guidelines/python.md#check-the-version-before-using-an-api).

## Display names

Override `_compute_display_name`, not `name_get`, and list the fields it uses
in its `depends` (odoo/odoo#122085).

## Module hooks

A module hook (`pre_init_hook`, `post_init_hook`, `uninstall_hook`) receives
`env` as its argument (odoo/odoo commit `b4a7996e9676`).

## Paths

Get the path of a file with `file_path`, with its new argument syntax, not
`get_resource_path` (odoo/odoo#135607).

## Views

- Do not use `active_id`, `active_ids` or `active_model` in the context of a
  view (for example of a smart button). Use `id` for `active_id` and the
  model name written in the context for `active_model`. `active_ids` has no
  direct replacement: it depends on what you want to achieve, and it is a
  rare case. A warning is issued if you keep them (odoo/odoo commit
  `daf05d48ac76`).
- The XML attributes `attrs` and `states` are no longer used. Write the
  equivalent Python expression in `invisible`, `required` or `readonly`:
  `attrs="{'invisible': [('name', '=', 'red')]}"` becomes
  `invisible="name == 'red'"` (odoo/odoo#104741).
- A field with `readonly=True` on the model cannot be imported with the
  import tool. Avoid it where you can and set `readonly` on the views.
- In a tree view, hide a column with `column_invisible="1"`. With
  `invisible="1"` the column is shown, but empty.
- A settings view (one that inherits from `res.config.settings`) uses the
  simplified syntax (odoo/odoo#106425):
  - `<app>` is the element of the application section, not
    `<div class="app_settings_block ...">`;
  - `<block>` is a container, not `<div class="o_settings_container ...">`,
    and its title goes in the `title` attribute, not in an `<h2>`;
  - `<setting>` is one setting, not `<div class="o_setting_box ...">`, and
    the fields, labels and paragraphs go inside it;
  - the divs with the classes `o_setting_right_pane` and
    `o_setting_left_pane` are not needed.
- Do not put `owl="1"` on an OWL template: all templates are OWL now
  (odoo/odoo#130467).

## Tests

- Odoo blocks by default the external calls of the `requests` library in
  tests. Mock them:

  ```python
  from unittest.mock import Mock, patch

  @patch("requests.get")  # or requests.post
  def test_foo(self, mock_get):
      mock_get.return_value = Mock(status_code=200, json=lambda: PAYLOAD)
      ...
  ```
  Letting the real call through (restoring `requests.Session.send` in
  `setUpClass`) is a last resort and is discouraged.
- Use `BaseCommon` as the base class of the tests: it reduces the overhead of
  tracking and speeds up the test suite.
