# Odoo 19.0

Rules for writing an addon for 19.0: which API to use, and which one no
longer exists or is replaced. The source is the framework changes listed in
the OCA migration guide to 19.0, with the Odoo change that introduced each
one (`odoo/odoo#...`). It is not a list of changes to the data model of each
Odoo module (see the `upgrade_analysis.txt` files of the OpenUpgrade
project), and the steps to migrate a module are not part of this file.

For constructs that are not listed here, follow
[Check the version before using an API](../guidelines/python.md#check-the-version-before-using-an-api).

## Groups and privileges

- A group belongs to a privilege. `res.groups` has `privilege_id`, which
  points to the model `res.groups.privilege`; `category_id` no longer exists.
  When you define a new permission section, create its privilege too
  (odoo/odoo commit `33637d137ed5`).
- The field that links a record to groups is `group_ids`, not `groups_id`, on
  `res.users`, `ir.ui.view`, `ir.ui.menu`, `ir.actions`, `ir.actions.report`
  and `website.page.properties`. Use it in views, menus, actions and reports
  (odoo/odoo#179354).

## Environment shortcuts

- Use `self.env.cr`, `self.env.uid` and `self.env.context`, not `self._cr`,
  `self._uid` and `self._context`.
- Use `self.env.tz` for the timezone, not manual handling with `pytz` or
  `self.env.context.get("tz")` (odoo/odoo#221541).
- Import `SUPERUSER_ID` from `api`, not from `odoo` itself (odoo/odoo commit
  `d6a955f10483`).
- Use `odoo.tools.urls.urljoin`, which covers more cases, not
  `urllib.parse.urljoin` (odoo/odoo commit `977e62d91f3e`).

## Domains

- Build domains with `odoo.fields.Domain`, not with `odoo.osv.expression`
  (odoo/odoo#217708). Prefer `Domain` objects to lists wherever a domain is
  passed (searches, `filtered_domain`...): the syntax is clearer and the
  domain is better optimized.
- The search method of a computed field that is not stored returns a
  `Domain`, not a list (odoo/odoo commit `4f0d4670ed`).
- In such a method, do not expect the operator and the value of the original
  search: the domain optimizer can rewrite them. For
  `model.search([("boolean_field", "=", True)])`, the method
  `_search_boolean_field` receives the operator `in` and the value
  `OrderedSet([True])`, not `=` and `True`.
- Domains accept dynamic date parameters (odoo/odoo#216665), and the
  `odoo.domain` and `odoo.Domain` API is available to manipulate them
  (odoo/odoo#170009).
- `name_search` takes the parameter `domain`, not `args` (odoo/odoo commit
  `e35bcedab200`).

## Models, fields and decorators

- Declare constraints and indexes with variables that instantiate
  `models.Constraint` and `models.Index`, not with `_sql_constraints`
  (odoo/odoo#175783).
- Use the field parameter `bypass_search_access`, not `auto_join`
  (odoo/odoo#219627).
- Use `_read_group` in a backend process and `formatted_read_group` in a
  public call, not `read_group` (odoo/odoo#163300).
- Archive with the explicit `action_archive` and `action_unarchive`, not
  `toggle_active` (odoo/odoo#183691).
- Put `@api.private` on a method that has no initial underscore and must not
  be reachable by the external API (odoo/odoo#195402).
- Do not use `@api.returns`: the decorator is removed (odoo/odoo#182709).
- Cache with the regular `@ormcache`, passing the context keys as parameters
  read with `self.env.context.get("key")`. `@ormcache_context` is replaced
  (odoo/odoo#220725).

## Controllers

The `@route` decorator takes `type="jsonrpc"`, not `type="json"`
(odoo/odoo#183636).

## Views

- A `<group>` tag in a search view has no `string` or `expand` attribute
  (odoo/odoo#220023).
- Groups on a view, a menu or an action are set with `group_ids` (see
  [Groups and privileges](#groups-and-privileges)).

## Tests

- Disable tracking in the whole test environment with `tracking_disable` in
  the context, or use `BaseCommon` as the base class of the tests when you
  need to set up the company, the currency, the users and the groups in a
  special way:

  ```python
  cls.env = cls.env(context=dict(cls.env.context, tracking_disable=True))
  ```
- Demo data is not installed by default for tests. Odoo advises not to rely
  on it: create the data in the tests themselves.
- Load a fake model in a test natively. The `FakeModelLoader` of the
  `odoo-test-helper` library is not needed:

  ```python
  from odoo.orm.model_classes import add_to_registry

  @classmethod
  def setUpClass(cls):
      super().setUpClass()
      from .fake_models import FakeModel
      add_to_registry(cls.registry, FakeModel)
      cls.registry._setup_models__(cls.env.cr, ["fake.model"])
      cls.registry.init_models(cls.env.cr, ["fake.model"], {"models_to_check": True})
      cls.addClassCleanup(cls.registry.__delitem__, "fake.model")
  ```
