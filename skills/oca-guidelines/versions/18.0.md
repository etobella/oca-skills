# Odoo 18.0

Rules for writing an addon for 18.0: which API to use, and which one is
removed or replaced. The source is the framework changes listed in the OCA
migration guide to 18.0, with the Odoo change that introduced each one
(`odoo/odoo#...`). It is not a list of changes to the data model of each Odoo
module (see the `upgrade_analysis.txt` files of the OpenUpgrade project), and
the steps to migrate a module are not part of this file.

For constructs that are not listed here, follow
[Check the version before using an API](../guidelines/python.md#check-the-version-before-using-an-api).

## Views

- The type of a list view is `list`, not `tree`, everywhere: Python, JS and
  XML. Keep an XML id that has `tree` in its name, so that dependent modules
  do not have to change. The context key that selects a list view is
  `list_view_ref`, not `tree_view_ref` (odoo/odoo#159909).
- The chatter is `<chatter />`, not `<div class="oe_chatter">` with its inner
  elements (odoo/odoo#156463).
- A field used in an expression (`invisible`, `column_invisible`,
  `readonly`, `required`, `context`, `domain`) is added to the view
  automatically, as an invisible one. Do not add a field with
  `invisible="True"` or `invisible="1"` only for that (odoo/odoo#137031).
- A kanban view uses the simplified architecture (odoo/odoo#167751):
  - `card` is the definition of the card, not `kanban-box`;
  - the elements are regular `<field>` definitions, with no `<div>` around
    them, and a `class` attribute can decide where they go;
  - `kanban-tooltip` does not exist;
  - a color picker is `<field name="color" widget="kanban_color_picker"/>`,
    not `<ul class="oe_kanban_colorpicker" data-field="color"/>`;
  - the image of a many2one is
    `<field name="parent_id" widget="image" options="{'preview_image': 'document'}"/>`.
- Set the field `path` on an `ir.actions.act_window` record, for a nicer URL.

## Access API

- Check the groups of the user with `self.env.user.has_group(...)`.
  `user_has_groups` is removed (odoo/odoo#151597).
- `check_access()` replaces `check_access_rights()` and `check_access_rule()`,
  and `_filtered_access()` replaces `_filter_access_rules()` and
  `_filter_access_rules_python()` (odoo/odoo#179148).

## ORM

- Override `_search_display_name`, not `_name_search`, which is gone.
- Use `_has_cycle()`, not the deprecated `_check_recursion()`.
- `copy` and `copy_data` work on multiple records: `copy_data` returns a list
  of values and `self` can be a multi-record set (odoo/odoo#154132).
- On a field, use the attribute `aggregator`, not the obsolete
  `group_operator`.
- A search on a non-stored related field raises an exception; it does not
  only log a warning any more.
- To change the result of searches, override `search_fetch`, not `search`:
  `search` is not always called in this version.
- Get a registry with `from odoo.modules.registry import Registry` and
  `Registry(db_name)`, not `from odoo import registry` and
  `registry(db_name)` (odoo/odoo#178784).
- Translate with `self.env._` instead of `_`: it is faster in some cases
  (odoo/odoo#174844).

## JavaScript

- Do not write `/** @odoo-module **/` at the top of a JS file
  (odoo/odoo#142858).
- A test tour does not use `extra_trigger`: add an independent step that has
  that condition as its `trigger`. Do not write `test: true,` in the
  definition of a tour.

## Tests

Disable tracking in the whole test environment with `tracking_disable` in the
context, or use `BaseCommon` as the base class of the tests when you need to
set up the company, the currency, the users and the groups in a special way:

```python
cls.env = cls.env(context=dict(cls.env.context, tracking_disable=True))
```
