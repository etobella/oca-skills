# Odoo 20.0

Rules for writing an addon for 20.0: which API to use, and which one no
longer exists or is replaced. The source is the framework changes listed in
the OCA migration guide to 20.0. It is not a list of changes to the data
model of each Odoo module, nor of business methods (see the
`upgrade_analysis.txt` files of the OpenUpgrade project), and the steps to
migrate a module are not part of this file.

For constructs that are not listed here, follow
[Check the version before using an API](../guidelines/python.md#check-the-version-before-using-an-api).

## Access rows and record rules are one model

The access rows (`ir.model.access`) and the record rules (`ir.rule`) are one
model, `ir.access`, usually loaded from a CSV file, `security/ir.access.csv`.
Write the access of a module with it. The Odoo change that introduced it
(`odoo/odoo#166359`) has examples of the format.

## Icons

Use Material Design icons. Font Awesome icons, declared with
`class="fa-..."`, are replaced; follow the Odoo guide for the icons.

## Tests

Tests that use `BaseCommon` as the base class run by default with a plain
internal user with no extra permissions. If a test needs the superuser
(`uid=1`), set `_test_user_groups = None` in the test class. The alternative
is to list the groups the test needs, as strings, in that variable; it can
have side effects depending on the modules loaded when the tests run.

## Widgets

The `selection_badge` widget is split by field type: use `badges_selection`
for selection fields and `badges_many2one` for many2one fields.
