Rules for Odoo 16.0, 17.0, 18.0 and 19.0, on top of `generic.md`. A module of
one of these versions has `version` starting with `16.0.`, `17.0.`, `18.0.` or
`19.0.`.

# Owl in 16 to 19

- Components of this range use the Owl 2 API. Check the version of Owl that
  the Odoo version ships (the header of `web/static/lib/owl/owl.js`) before
  you rely on an API.
- Write the Owl 2 API: `useState` for reactive state, `useRef` for an element,
  static `props` to declare the props, and `useEffect(fn, () => [deps])` with a
  function that returns the dependencies. `useLayoutEffect`, `useSubEnv`,
  `useEnv`, `onWillRender` and `render()` also exist in Owl 2.
- Do not write Owl 3 code: signals, `useOnChange` and plugins (see
  `20-and-later.md`) do not exist in this range.
- For derived state, write a plain function (see
  [Avoid getters](generic.md#avoid-getters)), and call it from the template.

# Module header and templates

- From 18.0 do not write `/** @odoo-module **/` at the top of a JS file. In
  16.0 and 17.0 keep it: check that the version does not need it before you
  remove it.
- From 17.0 do not put `owl="1"` on an Owl template: all templates are Owl.
  In 16.0, check whether the template needs it.

# Assets and styles

- In 16.0 declare an XML assets template in the regular bundle of its scope
  (`web.assets_backend`, `web.assets_frontend`...), not in the fake bundle
  `web.assets_qweb`.
- From 16.0 reports, QWeb templates and website elements use Bootstrap 5, not
  Bootstrap 4.

The tests and the tours of this range depend on the version: QUnit in 16.0 and
17.0 (`tests-qunit.md`), Hoot from 18.0 (`tests-hoot.md`).

# Icons in 16 to 19

The icons of this range are Font Awesome icons (`class="fa fa-..."`). Give
them a role and a label as in
[Give every icon a role and a label](generic.md#give-every-icon-a-role-and-a-label),
with the `fa` classes in place of `ICON`. From 20.0 they are Material Design
icons.

# Constructs in 16 to 19

Before you use one of these, check that the source of the module's version
has it, and say so if you could not look.

| Construct | What to know |
| --- | --- |
| `patch(...)` of `@web/core/utils/patch` | Check its signature in the version: it is the call you will write most. |
| the `browser` object of `@web/core/browser/browser` | Check whether the version's tests patch timers and `window` members through it, or mock them on `window`. Use what the code around uses. |
| `@web/core/utils/concurrency` (`KeepLast`, `Mutex`) | Check that it exists in the version. |
